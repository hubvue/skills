# Quality Checklist

Before finalizing documentation, check the following.

## Clarity

- Is the responsibility explained in plain language?
- Can a new engineer understand what this target is for?
- Are section titles useful and specific?

## Practicality

- Does the doc explain how to use the target?
- Is there at least one meaningful example when evidence allows?
- Are caveats explained instead of hidden?

## Accuracy

- Are all important claims supported by code evidence?
- Are unsupported assumptions removed or marked as inference?
- Are constraints stated carefully?

## Completeness

- Does the doc cover the most important public surface?
- Does it mention prerequisites where needed?
- Does it mention likely misuse or edge cases where valuable?

## Structure

- Does the chosen template match the scope?
- Is the ordering logical for the reader?
- Is duplicate explanation reduced?

## Update Mode

If updating an existing document:
- Was useful original structure preserved?
- Were outdated claims corrected?
- Were missing sections added?

## Final Standard

A strong document should let a reader answer:

- What is this?
- Why does it exist?
- When should I use it?
- How do I use it safely?
- What should I be careful about?
