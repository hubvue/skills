# Phase 05: Value

## Purpose

Assess whether solving the validated pain creates sufficient user, business, and engineering value.

## Inputs

- `04-painpoints.md`
- `research/04-painpoints-research.md`
- relevant earlier artifacts and `sources/sources.json`

## Work

1. Connect each value claim to a validated pain.
2. Assess user outcomes, business outcomes, strategic leverage, and engineering leverage.
3. Estimate value magnitude and confidence without inventing precision.
4. Compare expected benefit with adoption, delivery, and operating cost.

Suggested search questions:

- Do users pay for comparable outcomes?
- How are comparable products priced or monetized?
- What measurable losses does the problem cause?

## Input quality gate

Require at least one validated pain, an identifiable beneficiary, and enough context to judge the desired outcome. Use this internal question priority for user-owned value choices:

1. “解决这个痛点后，核心用户最重要的可观察变化是什么？”
2. “这个变化对业务最直接的意义是什么？”
3. “你愿意为验证这项价值承担多大的投入？”

Pass when user value is concrete and any claimed business or engineering value can be evaluated rather than merely asserted.

## Output

Write `05-value.md` with:

- user, business, and engineering value;
- value type and strength;
- benefit-versus-cost reasoning;
- priority recommendation;
- value risks;
- Evidence Block;
- phase conclusion and downstream handoff.

Write `research/05-value-research.md`.

## Output quality gate

Verify that every value claim traces to a validated pain, beneficiary and outcome are named, magnitude and confidence are not falsely precise, costs are considered, and the priority recommendation follows from the comparison.

## Gate

`continue` when value is material enough to assess feasibility. Map weak value to `idea_pool` or `deferred`; do not approve a requirement solely because the solution is interesting.
