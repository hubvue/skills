# source-analysis

## Purpose

Analyze the provided source material before converting it into a skill.

## Checkpoints

### 1. Source type
Identify whether the material is mainly:

- component library docs
- SDK docs
- utility docs
- README
- examples
- FAQ
- migration guide
- standards / conventions
- mixed material

### 2. Coverage
Check whether the material contains:

- factual API or component information
- setup or integration guidance
- examples
- scenario guidance
- troubleshooting content
- migration information
- explicit rules or conventions

### 3. Strengths
Record what the material supports well.

Examples:
- strong factual grounding
- good setup instructions
- many examples
- clear migration mapping

### 4. Weaknesses
Record what is missing.

Examples:
- no scenarios
- little troubleshooting
- no “when to use / avoid”
- no migration notes
- limited examples

### 5. Suitability judgment
Judge whether the docs support:

- explanation only
- explanation + recommendation
- explanation + code generation
- troubleshooting
- migration
- standards enforcement

## Output shape

- source summary
- strengths
- weaknesses
- likely capability ceiling
- missing information that affects skill quality
