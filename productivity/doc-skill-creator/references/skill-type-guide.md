# skill-type-guide

## Purpose

Decide what kind of skill the target documentation should become.

## Main skill types

### 1. Usage assistant
Best for:
- component libraries
- SDKs
- utility libraries

Typical abilities:
- explain usage
- recommend what to use
- compare options
- provide minimal examples

### 2. Code generation assistant
Best for:
- setup docs
- integration docs
- SDK docs
- code pattern docs

Typical abilities:
- generate starter snippets
- produce integration templates
- fill in required wiring

### 3. Troubleshooting assistant
Best for:
- FAQ
- issue collections
- debugging notes
- support docs

Typical abilities:
- diagnose common issues
- explain likely causes
- propose checks and fixes

### 4. Migration assistant
Best for:
- upgrade guides
- version migration docs
- breaking changes docs

Typical abilities:
- map old usage to new usage
- explain replacements
- warn about risks

### 5. Standards assistant
Best for:
- conventions
- internal standards
- design system rules
- integration policies

Typical abilities:
- recommend compliant approaches
- enforce preferred patterns
- reject non-standard solutions

## Guidance

- Pick one primary skill type
- Add secondary types only if the source material clearly supports them
- Do not over-scope the target skill
