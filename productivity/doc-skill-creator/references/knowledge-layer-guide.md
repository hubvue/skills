# knowledge-layer-guide

## Purpose

Separate extracted knowledge into maintainable layers.

## Layers

### 1. Facts
Use for:
- APIs
- props
- events
- methods
- configuration keys
- setup steps
- documented limitations

Only source-grounded information belongs here.

### 2. Rules
Use for:
- when to use something
- when to avoid it
- preferred combinations
- constraints and prerequisites

Mark rules as:
- documented
- derived

### 3. Scenarios
Use for:
- real user goals
- task-oriented mappings
- recommended solutions for common cases

### 4. Examples
Use for:
- minimal examples
- scenario examples
- integration examples
- migration examples

### 5. Pitfalls
Use for:
- common mistakes
- edge cases
- misconceptions
- troubleshooting patterns

### 6. Migration
Use for:
- old-to-new mapping
- replacements
- breaking changes
- transition notes

### 7. Gaps
Use for:
- what the docs do not provide
- what weakens the target skill
- what should be added later

## Rule

Do not mix these layers carelessly.
The clearer the separation, the more reliable the target skill.
